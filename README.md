# Covenia Competition MVP v0.8

Covenia 是嵌入千牛客服工作台右侧的消费者体验责任副驾。它联动聊天、图片、订单与售后工单，把消费者已经提交的证据和客服作出的服务承诺转化为可追踪、可执行、可主动补救的服务责任，在动作发生前阻止重复伤害，并持续推动问题真正闭环。

> 已经知道的信息，不再问第二遍。  
> 品牌答应的事情，不让消费者催第二次。

核心洞察：消费者不应该成为自己售后问题的项目经理。

## 唯一核心创新

客服的一句自然语言承诺不会只停留在聊天记录里。Covenia 通过“承诺编译与执行（Promise-to-Action）”完成：

```text
原始聊天与图片
→ 恢复已知事实和已有证据
→ 抽取并校验服务承诺
→ 生成体验责任账本
→ 动作前体验防线
→ 解决路径与人工批准
→ 服务进度回执
→ 跨时间检查、升级与主动通知
```

体验责任账本存储责任；体验防线保护责任不被下一动作破坏；责任闭环让责任在聊天结束后继续运行；服务进度回执只是消费者可见的简明视图，不是新的独立系统。

## 赛事数据基线

官方文件为全量模拟数据，共包含 8 个工作表：1 个数据说明与 7 个业务数据表。可核验规模为：

- 138 个会话、998 条聊天消息。
- 113 笔订单。
- 29 条图片消息，分布于 29 个会话；工作簿只提供图片路径引用，不包含实际图片文件。
- 80 条五类工单：24 条补发换货、13 条线下打款、15 条物流、10 条不良反应、18 条售后退货。
- 28 条工单当前不是“已完结”状态。

赛事模拟数据用于系统开发、跨表关联和场景审计，不用于证明真实市场发生率。图片推理所需素材由团队自制或合成，并明确标记数据来源。

## 唯一英雄场景

英雄场景以赛事会话 `S00001` 为原型：消费者反馈粉底液泵头损坏，提交一条图片消息；客服确认包装破损、创建换货单并承诺 48 小时内发出；补发换货工单仍在进行中且已有补发物流单号。

比赛压力测试补充第二次进线、两张美妆证据图片、评估时间和物流节点。所有扩充字段均标记为“基于赛事数据结构构建的测试数据”，不冒充原始赛事记录。

## Competition MVP

- 读取赛事 Excel 的 7 个业务表并建立会话、订单与工单关联。
- 在千牛右侧窄栏展示已知事实、当前禁止动作与下一解决动作。
- 由一个多模态模型从原始聊天和团队测试图片生成结构化旅程抽取。
- 从聊天中抽取并分类服务承诺，不在运行输入中预填承诺结论。
- 三个案例由同一链路输出 `INTERVENE / ALLOW / HUMAN_REVIEW`。
- 人工确认后创建可追踪服务责任与消费者可见的服务进度回执。
- 一次模拟物流事件真实触发状态更新、催办候选与主动通知草稿。
- 轻量管理区只展示赛事数据能够支持的工单状态和待调查假设。

## 明确边界

Covenia 不替代千牛，不自动认定质量责任，不自动退款、赔偿或补发，不宣称接入欧莱雅生产系统。客服自然语言中的模糊安抚、条件表达、越权承诺和高风险赔付不会直接生成生效责任；需要审批的承诺只有在人工批准后才进入倒计时。

## 设计冻结

本版冻结产品主链和比赛实现边界。`schemas/` 与 `docs/05-api-and-ui.md` 是实现接口的唯一基线；所有请求、返回、错误、幂等和时序规则均以这两处为准。后续得分增长来自真实界面、模型链路、调研与独立评测，不再增加独立模块、页面或售后场景。
