# 04｜责任闭环与服务进度回执

## 1. P0 目标

有效服务承诺不会因聊天结束而消失。P0 将 `S00001` 的“48 小时内发出”转成持续运行的服务责任，并用一次物流分支证明状态真的会变化。

## 2. 责任对象

人工确认后写入：

- 责任类型：`REPLACEMENT_FULFILLMENT`。
- 面向消费者责任方：`BRAND`。
- 当前执行方：赛事工单中的发货仓库或模拟物流执行方。
- 当前里程碑：`AWAITING_CARRIER_PICKUP`。
- 承诺截止时间：由聊天承诺计算。
- 下一检查时间：不晚于承诺截止前的预警节点。
- 真正完成条件：补发商品送达，而不是工单创建或物流单号生成。

内部执行方变化不把责任重新推给消费者。

## 3. 服务进度回执

服务进度回执由责任账本生成并通过原聊天窗口发送，不要求消费者下载新应用或管理新页面。

消费者只看到：

```text
已收到：粉底液泵头损坏图片，无需再次提交
正在处理：换货商品待物流揽收
最迟更新：2026-05-07 10:27 前
如未按时发出：品牌将主动催办并通知新的处理时间
消费者当前操作：无需操作
```

回执不显示内部责任人、情绪标签、风险分数或规则推理，也不称为法律凭证。

## 4. 物流事件分支

P0 支持同一接口下两个可变输入：

### `SHIPMENT_PICKED_UP`

- 责任保持 `ON_TRACK`。
- 更新为已揽收和可查询物流。
- 向消费者生成真实进展回复。
- 不创建仓库催办任务。

### `SHIPMENT_NOT_PICKED_UP`

- 若尚未到期：保持 `ON_TRACK`，创建内部预警和下次检查时间。
- 若已到期：Case 进入 `AT_RISK`，责任进入 `AT_RISK`。
- 预填仓库催办任务，生成主管升级候选和消费者主动通知草稿。

事件按钮调用后端接口，不允许直接修改前端状态。

## 5. 人工修改

人工可以修正承诺分类、执行方、期限和业务动作。修正后以人工事实为最高优先级，旧计划停止继续执行，防止 Agent 错误追踪。

## 6. 完成定义

`工单创建 ≠ 已发出 ≠ 已揽收 ≠ 已送达 ≠ 消费者问题真正解决`。

只有完成条件满足后 Case 才进入 `RESOLVED`。Competition MVP 可以演示到已揽收或风险升级，但不得把“生成物流单号”描述为完成。

## 7. P0 不要求

- 企业级事件总线、复杂重试与多货件并发。
- 仓库、物流、财务生产接口。
- 自动批准退款、赔付或重新补发。

P0 要求的是同一服务责任在事件前后真实更新，而不是完整企业基础设施。
