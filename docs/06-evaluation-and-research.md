# 06｜现实、运行与对照证据

Covenia 必须形成三条彼此独立的证据链，不能用赛事 Mock 数据同时证明痛点和产品效果。

## 1. 赛事数据证据

赛事文件用于证明系统能适配千牛工作台和给定数据结构：

- 138 个会话、998 条消息、113 笔订单。
- 29 条图片消息，但工作簿没有实际图片文件。
- 80 条五类工单，其中 28 条不是“已完结”状态。
- `S00001` 可支持泵头损坏、图片已提交、包装破损确认、换货工单、48 小时承诺和进行中履约链。

赛事数据全部是官方提供的 Mock 数据，只能证明系统可运行和字段适配。

## 2. 用户与业务现实证据

保持最小够用版：

- 80–150 份短问卷，目标约 100 份。
- 5–8 名消费者深访。
- 3–5 名客服或售后人员短访，重点验证记录可见但权限、协作和执行仍可能中断的问题。
- 真实匿名售后旅程 3–5 条为加分项，拿不到不阻塞系统开发。

最终展示只需要 3 个统计数字、2–3 句匿名原话和 1 条真实旅程。

## 3. 人工标注运行证据

从 138 个赛事会话中选择并人工标注 30 个案例，标注：

- 已知事实与已有证据。
- 证据覆盖范围和缺失项。
- 承诺原文、承诺类型和生效状态。
- 消费者意图、体验成因与潜在需求。
- 待履行责任、禁止动作和推荐解决路径。

其中 20 个用于开发与回归，10 个作为非开发成员保管的留出测试；如时间允许扩充到 30–50 个留出案例。

## 4. 对照实验

比较三种系统：

| 系统 | 历史恢复 | 承诺识别 | 重复索证控制 | 跨时间追踪 |
|---|---|---|---|---|
| 当前会话 LLM | 否 | 仅当前会话 | 弱 | 否 |
| 全历史 LLM | 是 | 可抽取 | 不稳定、难审计 | 否 |
| Covenia | 是 | 抽取、分类并校验 | 透明规则约束 | 是 |

核心指标：

- 证据复用判断正确率。
- 合理重新索证放行率。
- 承诺抽取与类型分类正确率。
- 禁止动作判断正确率。
- 物流事件后的状态与动作正确率。
- 人工覆盖率和平均处理时长变化。

## 5. 抗演员路径验证

评委或非开发成员至少可以修改一项输入：图片清晰度、当前商品、承诺时间或物流状态。系统必须从同一模型、状态和规则链产生不同结果，不能按 Case ID 返回固定答案。

## 6. 报告规则

- Ground Truth 不进入模型或运行输入。
- 小样本逐案例展示，不包装为生产准确率。
- 错误、争议和人工覆盖案例保留。
- 未完成结果标记“进行中”，不填写预测数字。
- Mock 数据、团队扩充、真实调研和系统评测分别标识来源。
