# 02｜AI 图文抽取与承诺编译

## 1. P0 模型策略

默认基线使用 `Qwen/Qwen2-VL-2B-Instruct` 统一处理聊天与团队测试图片。阿里云算力用于模型部署或推理服务；是否切换到同系列更高版本由实际资源测试决定，但对外只登记最终使用的一个模型版本。

所有提供方通过统一 `ModelProvider` 输出同一 `ExtractedJourney`，业务规则不绑定具体云 API。

## 2. 多模态模型必须影响决策

模型不是只输出“疑似泵头损坏”，而要结构化输出：

- 图片商品是否与订单粉底液 SKU 匹配。
- 识别对象是正装还是赠品。
- 可见组件是泵头、瓶盖、瓶身还是外包装。
- 问题部位、商品整体和包装环境是否被覆盖。
- 图片可读性、问题可见性与置信度。
- 是否存在产品完整性或卫生使用风险信号。

这些观察进入确定性证据判断；如果 SKU 不匹配则可放行合理索证，如果无法可靠识别则进入人工复核。

## 3. 因果式体验理解

模型输出：

- 消费者意图。
- 体验表达原文。
- 引发体验恶化的服务事件。
- 消费者潜在需求。
- 对优先级和下一动作的影响建议。

情绪不会形成独立指数，也不能直接决定换货、退款或赔偿。

## 4. 承诺编译

承诺编译不是把所有带时间的客服话术机械变成倒计时，而是四步：

1. 从原始聊天抽取承诺原文、时间、条件和动作对象。
2. 使用模型区分标准承诺、需审批、条件承诺、疑似错误和模糊安抚。
3. 使用工单、权限与模拟政策规则校验是否可以生效。
4. 将通过校验的承诺写入体验责任账本，并生成下一检查时间。

`S00001` 中“换货单已创建，48 小时内发出”同时得到聊天原文和补发换货工单支撑，可作为主演示中的有效服务承诺。

“尽快”“有结果第一时间联系”属于模糊表达，不单独生成确定截止时间；高风险赔付和不良反应处理必须人工确认。

## 5. 输入禁止项

不得向模型预填：

- 承诺是否有效或已经超时。
- 图片是否足够支持当前动作。
- 证据最终状态。
- 消费者输入是否完成。
- 当前责任方。
- 体验防线结果。

## 6. 输出失败处理

- Schema 不合法：重试一次。
- 仍失败或来源冲突：进入 `HUMAN_REVIEW`。
- 模型不可用：使用明确标记的缓存抽取结果；后续状态和规则仍真实运行。
- 灾备结果不得描述为实时模型推理。

## 7. 验收

- 至少一个案例从原始聊天和实际图片文件生成抽取结果。
- 图片观察真实改变 `VALID / MISMATCHED / NEED_HUMAN_REVIEW`。
- 承诺从聊天原文抽取并经过工单事实校验。
- 界面能展开查看来源消息、图片观察和模型版本。
- 修改图片或承诺文本后，输出可发生合理变化。
