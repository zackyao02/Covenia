# 07｜4 分钟演示与交付门禁

## 1. 主演示脚本

### 0:00–0:25｜消费者不应成为售后项目经理

展示 `S00001` 原始聊天：泵头损坏、图片已发、包装破损已确认、换货单已创建、48 小时内发出。

### 0:25–1:05｜从赛事数据恢复完整责任

导入聊天、订单、换货工单和团队测试图片。模型现场输出商品、泵头、证据覆盖、消费者意图和承诺原文；系统校验现有工单后激活 48 小时服务责任。

### 1:05–1:45｜发送前阻止品牌再次犯错

客服输入“麻烦再上传一下破损照片”并点击发送。Covenia 暂停发送，显示已有证据与规则事实，提供“查询补发进度”和“生成解决回复”。

### 1:45–2:25｜一句承诺开始运行

系统生成查询结果、仓库催办预填和消费者回复。人工确认后，右侧插件和聊天窗口同时出现服务进度回执：已收到什么、正在做什么、最迟何时更新、消费者无需操作。

### 2:25–3:15｜消费者还没催，Agent 已经行动

评委选择物流状态：

- 已揽收：更新真实进展，不创建催办。
- 未揽收且已到期：责任变为 `AT_RISK`，生成仓库催办、主管升级候选和主动通知草稿。

### 3:15–3:40｜从一个人到一类风险

展示赛事 Mock 数据中的 28 条非完结工单，以及一条明确标记为“人工标注压力测试”的重复索证流程假设。

### 3:40–4:00｜证据与收尾

展示调研和对照实验结果卡。

收尾：Covenia 让消费者不必记住品牌说过的每一句话，因为系统会把有效承诺变成持续运行的服务责任。

## 2. Challenge Mode

主 Demo 不切换其他案例。答辩时使用同一链路现场验证：

- 赠品证据与正装泵头问题不匹配 → `ALLOW`。
- 同一商品但图片模糊 → `HUMAN_REVIEW`。
- 修改物流为已揽收 → 不产生仓库催办。
- 修改承诺为“尽快” → 不生成确定截止时间。

## 3. 五道交付门

### 门 1｜数据真实进入

Excel 导入代码能够关联 `S00001` 的聊天、订单和换货工单；长数字 ID 不丢失精度。

### 门 2｜AI 真实

至少一个案例从原始聊天和实际图片文件生成 `ExtractedJourney`，承诺不在输入中预填。

### 门 3｜判断真实

三个案例从同一规则链输出三种结果，图片观察真实改变证据状态。

### 门 4｜责任真实运行

人工确认创建责任；物流事件通过接口触发状态、催办和通知变化，前端不能直接改状态。

### 门 5｜证据可核验

问卷、访谈、30 个人工标注案例和三组对照结果有独立产物；所有数据来源明确。

## 4. 灾备

- 模型失败：展示明确标记的缓存抽取结果，后续规则和事件链继续真实运行。
- 现场网络失败：使用本地模型或本地推理服务。
- 插件失败：通过同一后端接口展示输入和状态变化。
- 动效失败：使用静态责任时间线，但不伪造接口执行。

## 5. 提交前清理

对外材料不出现内部评分、团队昵称、版本争论、预测准确率或未完成治理项。最终 Word 在 Windows Word 中导出 PDF 并逐页检查中文、分页和图片。
