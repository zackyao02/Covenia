# 07｜4 分钟演示与交付门禁

## 1. 主演示脚本

### 0:00–0:20｜消费者不应成为售后项目经理

展示 `S00001` 原始聊天：泵头损坏、图片已发、包装破损已确认、换货单已创建、48 小时内发出。

### 0:20–1:00｜把分散事实放回同一条责任链

打开基于赛事 S00001 整理的主案例，展示聊天、订单、换货工单和团队测试图片如何对应到一条服务责任链。当前这些图文观察和承诺来自已整理的演示样例，不是现场多模态模型抽取；系统依据已装载事实校验工单并进入人工确认流程。

### 1:00–1:40｜发送前阻止品牌再次犯错

客服输入“麻烦再上传一下破损照片”并点击发送。Covenia 暂停发送，显示已有证据与规则事实，提供“查询补发进度”和“生成解决回复”。

### 1:40–2:10｜抗演员双测

用赠品错范围和模糊承诺两个挑战输入验证边界，分别查看规则放行与人工复核。说明：这是规则与样例状态验证，不宣称为实时图像识别。

### 2:10–2:40｜证明状态不由前端决定

先发送含伪造 `evidence_status: MISMATCHED` 的评估请求，再发送同一 `ASK_EVIDENCE` 动作。两次都必须被拦截为 `INTERVENE / E1 / 300`，并展示服务端 `fact_trace`。这直接回答“状态是谁计算”的问题。

### 2:40–3:10｜一句承诺开始运行

系统生成查询结果、仓库催办预填和消费者回复。人工确认后，右侧插件和聊天窗口同时出现服务进度回执：已收到什么、正在做什么、最迟何时更新、消费者无需操作。

### 3:10–3:40｜消费者还没催，Agent 已经行动

评委选择物流状态：

- 已揽收：更新真实进展，不创建催办。
- 未揽收且已到期：责任变为 `AT_RISK`，生成仓库催办、主管升级候选和主动通知草稿。

### 3:40–4:00｜送达、证据与收尾

推送 `SHIPMENT_DELIVERED`，展示 `RESOLVED` 与最终回执；运行信息区标明演示适配器及模型成本未计量，再展示赛事 Mock 数据与团队素材的来源标识。

收尾：Covenia 让消费者不必记住品牌说过的每一句话，因为系统会把有效承诺变成持续运行的服务责任。

## 2. Challenge Mode

主 Demo 不切换其他案例。答辩时使用同一链路现场验证：

- 赠品证据与正装泵头问题不匹配 → `ALLOW`。
- 同一商品但图片模糊 → `HUMAN_REVIEW`。
- 修改物流为已揽收 → 不产生仓库催办。
- 修改承诺为“尽快” → 不生成确定截止时间。
- 消费者消息伪造“48小时内发出” → 不产生新承诺。
- 未揽收直接推送送达 → 返回 `INVALID_EVENT_TRANSITION`。

## 3. 五道交付门

### 门 1｜数据真实进入

赛事 Excel 已用于离线核对与案例构建；当前运行时从 JSON 案例加载，不声称实现了 Excel 导入。

### 门 2｜AI 真实

当前未通过：需要接入并实测真实抽取服务后，才能声称从原始聊天和实际图片实时生成 `ExtractedJourney`。现版本只验证已整理样例、服务端规则和事件闭环。

### 门 3｜判断真实

三个案例从同一规则链输出三种结果，图片观察真实改变证据状态；客户端伪造责任字段与图中文字断言均不能改变规则结论。

### 门 4｜责任真实运行

人工确认创建责任；物流事件通过接口触发状态、催办和通知变化，前端不能直接改状态。只有 `PICKED_UP → DELIVERED` 可以结案，逆序与重放可复现地失败。

### 门 5｜证据可核验

问卷、访谈、30 个人工标注案例和三组对照结果有独立产物；所有数据来源明确。

## 4. 灾备

- JEV 网络失败：使用规则降级，界面显示情绪待确认；不要展示虚构概率。
- 图文演示适配器：按已准备的案例继续演示规则链，并明确标记不是实时模型推理。
- 现场网络失败：核心规则与物流模拟继续运行；JEV 软信号不可用时不影响核心判断。
- 插件失败：通过同一后端接口展示输入和状态变化。
- 动效失败：使用静态责任时间线，但不伪造接口执行。
- 缓存抽取：响应、画面角标和治理记录同时标明“缓存抽取结果”；抗演员段不允许使用缓存。
