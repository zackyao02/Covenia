# Covenia｜项目简介

**赛道：** 欧莱雅第二届美妆科技黑客松·数据共情者  
**产品形态：** 千牛客服工作台中的消费者体验责任副驾  
**项目阶段：** 比赛演示原型

## 我们解决什么问题

售后服务往往跨越多轮对话、图片、订单与工单。客服接手时需要重新拼接上下文，消费者则可能再次解释、重复提交材料或主动催问。Covenia 聚焦一个具体问题：**当聊天结束或客服交接后，已知证据和品牌承诺如何继续推动服务直到闭环？**

本项目不声称这一现象的行业发生率，也不使用未验证的商业效果数字。当前以赛题提供的模拟客服数据和可运行演示链路展示产品设计。

## 产品如何工作

1. 将聊天、图片、订单和售后工单关联，形成可回看的服务事实。
2. 从对话中保留承诺原文、责任方和时间信息。
3. 客服准备发送或处理动作时，检查证据范围、责任状态和禁止动作，提示是否应拦截、放行或人工复核。
4. 由客服确认责任方、下一次更新时间和消费者回复后，生成本地演示的服务责任记录。
5. 模拟物流节点变化，触发进度更新、催办候选、升级候选和服务回执。

## 技术与责任边界

- **确定性规则**决定证据范围、责任状态、禁止动作与事件时序。
- **JEV**可为情绪趋势和下一步建议提供概率化软信号，不替代硬规则，也不独立批准退款、补发或其他高影响动作。
- **人工确认**负责批准服务责任与回复。
- 当前图文结果由本地演示适配器读取预置案例，不是实时模型抽取；JEV 已完成一次合成数据 API 烟测，阈值尚未校准。前后端测试与本地浏览器业务闭环已通过。
- 工作台尚未接入千牛生产账号或真实消息发送；服务状态保存在进程内存；数据与图片均按项目声明区分赛事 Mock、团队测试素材与真实证据。

## 当前验证结果

前端测试 11/11 通过，后端测试 11/11 通过；本地浏览器已验证“查询进度—人工确认—未揽收催办—揽收—送达结案”主链。以上为原型工程验证，不代表实时多模态能力、真实用户效果、生产级稳定性或模型校准结果。

## 一句话

**不让消费者重复讲述；不让有效承诺在交接中消失。**
