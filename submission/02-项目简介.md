# Covenia｜项目简介

**赛道：** 欧莱雅第二届美妆科技黑客松·数据共情者  
**产品形态：** 千牛售后工作流中的承诺跟进副驾
**项目阶段：** 比赛演示原型

## 我们解决什么问题

售后服务往往跨越多轮对话、图片、订单与工单。客服接手时需要重新拼接上下文，消费者则可能再次解释、重复提交材料或主动催问。Covenia 聚焦一个具体问题：**消费者再次追问时，已交材料和品牌承诺能否被找回，并持续跟到兑现？**

本项目不声称这一现象的行业发生率，也不使用未验证的商业效果数字。当前以赛题提供的模拟客服数据和可运行演示链路展示产品设计。

## 为什么不是再做一个客服 AI

通用机器人擅长回答常见问题，回复助手擅长整理话术，标准售后工具擅长登记和流转工单。Covenia 聚焦一个更窄的断点：**客服已经在聊天中答应了后续处理，但下一次进线或跨团队交接时，没人记得这项承诺是否兑现。**它尝试把聊天中的承诺整理为责任方、更新时间、完成条件和逾期补救，并在发送或关键动作前阻止重复索证、责任倒推和未完成就结案。它不替代千牛已有能力，也不声称其他系统无法实现这些流程。

第一使用者是一线售后客服，主要受益方是管理多轮售后与跨团队履约的售后主管。简单 FAQ 和标准退款不是目标场景。

## 产品如何工作

1. 将聊天、图片、订单和售后工单关联，形成可回看的服务事实。
2. 从对话中保留承诺原文、责任方和时间信息。
3. 客服准备发送或处理动作时，检查证据范围、责任状态和禁止动作，提示是否应拦截、放行或人工复核。
4. 由客服确认责任方、下一次更新时间和消费者回复后，生成本地演示的服务责任记录。
5. 在比赛模拟中推进物流节点，观察按时履约、逾期补救、责任升级和送达结案如何改变回执。

## 技术与责任边界

- **确定性规则**决定证据范围、责任状态、禁止动作与事件时序。
- **JEV**可根据新对话提供情绪趋势和沟通建议；真实调用成功且返回概率时，界面展示“情绪恶化概率”百分比，并标注尚未校准、不代表准确率；规则兜底时不显示虚构百分比，也不替代硬规则或批准高影响动作。
- **人工确认**负责批准服务责任与回复。
- 当前图文结果由本地演示适配器读取预置案例，不是实时模型抽取；精华和防晒缩略图为 AI 生成的无品牌示意图，不代表真实商品包装。JEV 已完成合成数据 API 烟测，阈值尚未校准。演示会话可逐个重置并从初始案例重放。
- 工作台尚未接入千牛生产账号、真实消息发送、仓库物流或人工任务系统。事件与履约为比赛模拟；服务端状态保存在进程内存，浏览器本地保存演示会话，不等于生产持久化。数据与图片按项目声明区分赛事 Mock、团队测试素材与真实证据。

## 价值如何验证

试点应记录重复索证拦截率、承诺按时更新率、逾期补救完成率、二次进线率和单案处理时间，并与原流程做对照。当前没有真实用户对照实验，不宣称效率或客诉改善比例。工程与独立验收状态以 `QA-ACCEPTANCE.md` 和最新演示记录为准。

## 一句话

**客服可以结束一段对话，品牌不能忘记自己答应过什么。**
